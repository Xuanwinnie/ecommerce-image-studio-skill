# 後端與模型路由

## 選擇順序

1. 使用目前 Agent 已具備的圖片生成／編輯工具，減少額外安裝與 Key 暴露。
2. 使用者已指定且已設定的官方供應商或可信服務。
3. 使用者明確同意後，才新增其他後端；先說明資料會傳到哪裡、費用與保存政策。
4. 沒有可用後端時，仍可完成工作單、身份鎖、提示詞、尺寸規劃與 QA 計畫，不假裝已產圖。

## 依能力路由

| 任務 | 優先能力 |
|---|---|
| 白底主圖、局部修正 | 多參考圖、高保真 image edit、遮罩或局部編輯 |
| Logo／包裝文字保留 | 文字與細節保真、可用原圖編輯而非重新生成 |
| 情境圖與大量變體 | 良好構圖、參考圖一致性、合理成本與速度 |
| 模特上身、多角度 | 多圖條件控制、人物與商品身份一致性 |
| 含大量文字的資訊圖 | 先產底圖，再用排版工具合成；避免只依賴模型畫字 |
| 批次任務 | 可重試、可續跑、速率限制清楚、支援成本統計 |

不要把模型名稱當成能力保證。先用同一個 proof 與固定 QA 條件比較，再決定整批後端。

## 付費與安全門檻

- 生成前展示：供應商、模型、張數、尺寸、品質、估計呼叫數、已知單價、最高預算。
- 若無法可靠取得價格，明確標示「成本不確定」並取得同意。
- Key 僅來自環境變數或本機秘密儲存；不得寫進 `manifest.json`、提示詞、終端輸出或版本控制。
- 對第三方 OpenAI-compatible gateway，不因「相容」就視為官方；必須取得使用者明確選擇。
- 外部 API 失敗採有限次指數退避；預設最多 3 次。連續失敗、達預算或速率上限時停止。
- 支援 `dry_run` 時先輸出遮蔽 Key 的請求摘要，不傳送商品圖。

## 建議的後端介面

不同後端若要接進批次流程，至少統一以下欄位：

```json
{
  "provider": "user-selected-provider",
  "model": "capability-appropriate-model",
  "operation": "generate-or-edit",
  "prompt_file": "prompts/01-hero.txt",
  "reference_images": ["inputs/front.png"],
  "size": "2000x2000",
  "output": "final/01-hero.png",
  "dry_run": true,
  "max_attempts": 3
}
```

介面不得包含秘密；實際 Key 由程序環境注入。
