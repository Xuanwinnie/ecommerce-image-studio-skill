# 圖片類型與驗收重點

只讀取與本次任務相關的段落。所有圖片都要沿用 `manifest.json` 的商品身份鎖與已確認事實。

## 白底／英雄主圖

- 目標：在縮圖尺寸快速辨識商品，不改變實際 SKU。
- 輸入：至少一張清楚正面圖；複雜結構最好提供側面與背面。
- 禁止：虛構配件、錯誤 Logo、不可驗證獎章、促銷文案或誇大尺寸。
- QA：輪廓完整、透視自然、接地陰影合理、背景符合平台要求、主體占比合適。

## 情境／生活方式圖

- 場景要證明使用情境，不只是裝飾背景。
- 商品與人物的尺度、握持方式、安裝方向和物理接觸必須合理。
- 若情境可能暗示防水、耐熱、承重或醫療功效，必須先有已確認資料。
- 每張圖只承擔一個主要溝通目的，避免同一套圖全部使用相同構圖。

## 賣點資訊圖與尺寸圖

- 文案只來自已確認事實；數字與單位逐字比對。
- 先生成乾淨底圖，再以可控排版工具加字，通常比要求生成模型直接畫大量文字可靠。
- 尺寸圖需指出量測基準；若數據不完整，輸出無數字版式或等待資料，不得猜測。
- QA：手機縮圖仍可讀、字體層級清楚、文案沒有截斷或拼字錯誤。

## 多角度套圖

- 只從單張照片推導看不到的背面或內部結構時，要標成概念推定，不得當成實品事實。
- 最佳做法是使用多角度實拍作為共同參考。
- 固定背景、鏡頭高度、焦段感、陰影方向與商品比例；改變的是觀察角度。
- QA：孔位、接縫、按鈕、印刷、把手與配件在各角度一致。

## 模特上身／配戴

- 需要服裝或商品清楚照片；若有特定模特與姿勢，分別提供身份參考與姿勢參考。
- 保留布料、版型、圖案、Logo 位置和配件結構；不得因美化改變商品。
- 若要跨圖維持同一人物，建立人物身份鎖並在每次編輯使用同一參考圖。
- QA：手指、關節、耳掛、肩線、衣領、圖案連續性與商品接觸位置。

## A+／詳情頁模組

- 先做內容架構，再做模組圖片：英雄圖、核心價值、功能、細節、尺寸／規格、情境、包裝內容與 CTA。
- 同一頁建立共享的色彩、字體、留白與攝影規則。
- 優先保留可重新裁切的母版；平台尺寸應在交付當天查核。
- QA：敘事沒有重複、各模組商品一致、文字可讀、裁切後仍保留重點。

## 社群／廣告素材

- 先確認平台、版位、受眾、單一訊息、CTA 與使用者提供的優惠資料。
- 每個版位重新排版，不能只把同一張圖硬拉伸。
- 保留無字母版，方便在不同語言與政策下重製。
- 未經證實的倒數、稀缺、前後對比或功效宣稱不可加入。

## 批次任務

- 先用 1 個 SKU 做 proof，再擴展到整批。
- 每個 SKU 有獨立身份鎖、狀態、重試次數與成本紀錄。
- 設定並發、最大重試、總呼叫數或金額上限；達到上限立即停止並回報。
- 輸出 manifest，讓失敗項目可續跑而不是整批重做。
